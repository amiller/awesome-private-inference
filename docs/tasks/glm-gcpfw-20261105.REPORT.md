## Milestone 2 (same epoch): intel_rims content retention + bug fix

- `retain_rim_contents(history, rims, store_dir, now_iso)` in
  `watch/gce_tcb_endorsements.py`: on each daily run, any `intel_rims/*.textproto`
  whose listing md5 is new or changed is downloaded (fidelity checked against
  the listing md5 — transport integrity only, not authentication), stored at
  `data/gce-tcb-intel-rims/<base>/<md5>.textproto`, and appended to the history
  entry's `retained_versions`; `update_history` still logs the rewrite in
  `changes`.
- **Real rewrite captured live**: both rims were rewritten between the 19:46 and
  20:31 UTC runs today (intel-tdx generation 1793896056877610 → 1793910565198833);
  the committed history contains the change log + retained bytes of both versions'
  successors (the 19:46 bytes were superseded before content retention existed,
  so only the 20:29+ bytes are retained — md5s of the earlier versions are in the
  `changes` log).
- **Bugs found and fixed by the new unit tests**: (a) the GCS synthetic
  `intel_rims/` directory marker was being retained as a rim; retention now
  filters to `*.textproto` (`test_retain_rim_contents_ignores_directory_marker`);
  (b) retention was not idempotent when run without `update_history` in between —
  it now also dedupes against the newest retained version's md5
  (`test_retain_rim_contents_downloads_and_verifies_md5`).
- Fixtures: `tests/fixtures/gce-tcb/intel_rims/` — both objects (24 KB + 74 KB)
  byte-identical to the retained data/ versions, with manifest recording URL,
  generation, listing md5 (base64 + hex), capture time, and structure notes.
  Tests: `test_retained_rim_fixtures_match_listing_md5` (fidelity),
  `test_tampered_rim_content_fails_listing_md5` (negative control),
  `test_history_rim_retention_is_self_consistent` (committed history ↔ disk files
  ↔ change log).
- **Observation from the retained contents** (recorded in the fixture manifest):
  `intel-tdx-rim-prod.textproto` embeds three FMSPC-tagged Intel TCB-info JSON
  records (issueDate 2025-10-27, each carrying an Intel signature — NOT verified
  here, that is #18 territory) plus a DER `GCE-uefi-signer` leaf with
  serialNumber **36**, valid 2026-11-03 → 2031-11-03, chaining to the pinned
  root (serialNumber 1): Google pre-publishes next month's signer leaf in this
  file, and the root is still the pinned one. `confidential-space-rim-prod.textproto`
  embeds four self-signed COS `UEFI DB Key` certificates (v10, v20250203,
  v20260706, v20251004) plus the same signer leaf.

  2026-10, 5-year validity, signing that month's endorsements. Leaf rotation
  history is retained per endorsement in the history file.
