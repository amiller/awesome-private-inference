## Independent derivation (issue #27 criterion 1) — done

dstack-mr 0.6.3 at dstack-TEE/dstack `d7e15dc` was built on zed (rustc 1.92, no new
toolchain) and driven by a harness that mirrors upstream dstack's own verifier
(`dstack/verifier/verification.rs::compute_measurements`, the full-image TDX
path). Inputs: the published OS image archive (downloaded 2026-11-05;
`sha256(sha256sum.txt) == bd369a8c…` verified; all four manifest member digests
verified) and the deployment's authenticated `vm_config`. **All four registers
matched the observed quote body of evidence `01680c7c…` on first comparison**,
after the derivation had been written to disk. Observed registers were never
copied into the policy. Cross-check: dstack-mr's own integration test
(`dstack/dstack-mr/tests/tdvf_parse.rs`) pins the same MRTD `f06dfda6…` as its
v0.5.5 baseline — same firmware line as the 0.5.9 image.

## Issue #18 (ACI part) — done

Root cause: the adapter read `quote.tcb_status` from Phala's response; live
capture (fixture above) shows the `quote` object has exactly
`header, cert_data, body, verified`. Phala ships raw signed Intel
`quote_collateral.tcb_info` but computes no status verdict. Fix: the quote is
now verified locally with `dcap_qvl.get_collateral_and_verify` (same library as
the NEAR adapter; `probe-daily.yml` already syncs `--extra nearai`) and the real
status/advisory IDs are retained verbatim in `details`. Live result on the
retained quote, 2026-11-05: **UpToDate, no advisories**. Errors propagate (test
proves no null fallback).
