How to read the observatory

The homepage uses six route assessment axes, separate from raw adapter results. Read the versioned assessment rubric and dated source findings →

The unit of analysis is a client, model and request route. A brand can have several plaintext paths and different client policies. The route cards name the client mode, processes that may receive plaintext, published values, client acceptance and missing evidence.

Three distinct sets

Published

A provider serves a manifest, allowlist, release or reference history. Our capture retains exact bytes, origin, time and hash. Publication does not authenticate the file or prove deployment.

Accepted

An identified client policy permits a value. A built-in root, automatically refreshed manifest and locally pinned file have different authorities and rollback behavior.

Observed

A particular probe or request received evidence at one time. The check must bind authenticated measurement, recipient key, requested model and actual plaintext path before it supports a route verdict.

A mismatch may reflect a legitimate rollout, stale client, rejected update or attack. The change event requests review; it does not authorize a value. Reviewer decisions belong in separate signed or witnessed records.

What the current labels mean

Adapter accepted
The adapter accepted its scoped checks; this is not a full route verdict.
Adapter rejected
The adapter checked evidence and rejected it.
Not checked
Complete verification is unavailable; individual checks may have passed. Consult the stated missing proof.
Unsupported
The adapter cannot check this evidence surface.
Unavailable
Evidence or endpoint was unavailable; this is not a cryptographic rejection.
Stale
The latest evidence is too old for the stated freshness policy.
Not applicable
This check does not apply to this route.

A green adapter field is a result from that adapter's limited implementation. It is not an independent hardware, release or end-to-end request proof unless its verifier actually performed those checks. A missing credential is “not checked”; an HTTP failure is “unavailable”; a checked contradiction is “rejected.” Legacy snapshots may have only a boolean and narrower error context.

Reference capture and continuity

The publication probe makes bounded read-only HTTPS requests. Raw bodies are stored by SHA-256 and a derived latest index points to the last attempt and last success separately. Mirror comparison is byte agreement only. Changes in a public catalog's model or tier routing are distinct from volatile price text. The weekly model inventory is separate from the daily sentinel sample. Immutable events include route, old/new values, provenance and timestamp; no event is a deployment claim.

Reproduce the public baseline with python -m probes.references --catalogs. No key is required for the reference sources. Catalog endpoints may accept an existing API key through environment variables; credentials are never written into observations.
