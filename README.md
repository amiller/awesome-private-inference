## What this is

Private AI inference is a growing category. Providers claim "your prompts stay encrypted end-to-end inside a TEE." Some of them even expose `/attestation` endpoints you can verify. This repo:

1. **Re-verifies the attestation bundles daily.** Intel TDX quote → Phala verifier. NVIDIA GPU payload → NRAS. Signing key derivation → eth-keys. Nonce binding → report_data layout check.
2. **Sweeps pricing across overlapping catalogs.** Same Phala enclave reached via RedPill vs Venice → find the markup. List vs subscription $/M tokens.
3. **Publishes a neutral scorecard** of which verification layers each provider actually delivers — and which they skip.
4. **Points at devproof-style gap analysis** so ✅/❌ aren't confused with "private" vs "not private."

## What "private inference" would mean

A prompt should be observable only to:
- The sender (the user / the agent).
- Code that is **attested**, **reproducible from source**, and **bound** to the public key the prompt was encrypted to.

A complete proof therefore requires:

| Layer | What's checked |
|---|---|
| **TDX quote** | Intel's DCAP verifier accepts the enclave quote; TCB is current. |
| **GPU attestation** | NVIDIA NRAS returns `PASS` for the claimed GPU, bound to the same nonce. |
| **Report-data binding** | The TDX `report_data` cryptographically commits to `(signing_address, nonce)`. |
| **Key derivation** | `signing_address` is derivable from `signing_public_key` (keccak of uncompressed pubkey last 20 bytes). |
| **Compose-hash commitment** | The enclave's `mr_config` contains the sha256 of the running docker-compose, so the image is auditable. |
| **Backend attestation** | If there's a gateway → backend hop (e.g. NEAR cloud-api routing to model CVMs), the gateway must verify the backend's quote — not just forward it. |
| **Catalog → served** | The model the catalog advertises actually returns 2xx on a chat completion. |

A ✅ row in this registry means **only the layers we could automate**. The gaps are documented in every provider page.

## Known limitations

These are the reasons **no current provider is a complete end-to-end private inference solution**. They come from [amiller/devproof-audits-guide](https://github.com/amiller/devproof-audits-guide):

- **NEAR's gateway-side gap is narrowed, not closed.** cloud-api PRs [#485](https://github.com/nearai/cloud-api/pull/485) / [#513](https://github.com/nearai/cloud-api/pull/513) / [#552](https://github.com/nearai/cloud-api/pull/552) / [#558](https://github.com/nearai/cloud-api/pull/558) (Mar–Apr 2026) deleted the operator-controlled discovery URL and now inline-verify each backend's TDX/RTMR3/NRAS before serving. *Still open server-side:* `ALLOWED_COMPOSE_HASHES` is unset (any TCB-current TDX TD passes the gateway), and `DstackKms.kmsInfo` returns zero-length bytes (no on-chain anchor for the KMS root pubkey). The default `nearai-cloud-verifier` still runs only Block A. [Issue #224](https://github.com/nearai/cloud-api/issues/224) is still open. *Closed client-side* by [hermes-agent #12201](https://github.com/NousResearch/hermes-agent/pull/12201): strict-mode static anchor (`hermes_cli/anchors/nearai_mainnet.json`) that pins `(model → app_id, compose_hash, os_image_hash, kms_pubkey)` *and* per-model inner-compose closure `(compose_manager_attestation.actions[] → file, commit, file_sha256)`, plus a `model_name == requested_model` check. The latter immediately caught a live silent gateway substitution on 2026-05-05: `deepseek-ai/DeepSeek-V3.1 → Qwen/Qwen3.5-122B-A10B`. Under the closed-chain client the residual is anchor-refresh discipline (NEAR rotates composes and inner YAMLs often) plus the Phala upstream verifier's `verify_signature=False`. Full trace: [DEVPROOF-REPORT-revisit-2026-05-02](https://github.com/amiller/devproof-audits-guide/blob/near-ai-inference/case-studies/near-ai-private-inference/DEVPROOF-REPORT-revisit-2026-05-02.md).
- **RedPill's phala-simple fleet still boots `dstack-nvidia-dev` (live 2026-05-05).** Every `phala/*` model on RedPill is on `dstack-nvidia-dev-0.5.{5,8}-*`, which ships sshd + `debug-tweaks` + `tools-profile`. Combined with `DSTACK_AUTHORIZED_KEYS` in `allowed_envs` and a measured `pre_launch_script` that writes the host-supplied key to `/home/root/.ssh/authorized_keys` at boot, the operator gets host-network-namespace root SSH inside every CVM. NEAR's model fleet uses the prod image (`dstack-nvidia-0.5.5`); RedPill's Phala-direct fleet does not. Full audit: [redpill-federated-inference DEVPROOF-REPORT](https://github.com/amiller/devproof-audits-guide/blob/main/case-studies/redpill-federated-inference/DEVPROOF-REPORT.md).
- **Upstream verifier is attestation-only.** Phala's [`private-ai-verifier`](https://github.com/Phala-Network/private-ai-verifier) has no E2EE code; `signing_public_key` is never read anywhere in the repo. `model_verified: true` says nothing about prompt confidentiality. It also decodes NVIDIA and Intel Trust Authority JWTs with `verify_signature=False`. Full critique: [phala-private-ai-verifier case study](https://github.com/amiller/devproof-audits-guide/blob/main/case-studies/phala-private-ai-verifier/DEVPROOF-REPORT.md).
- **Skill-text backdoor.** Agent skill catalogs can silently skip every TDX-verification step while advertising `supportsE2EE`. Canonical example: [`veniceai/skills`](https://github.com/veniceai/skills) misnames the protocol, cites a 404 URL, and teaches none of the six verification steps — see [venice-private-inference case study](https://github.com/amiller/devproof-audits-guide/blob/main/case-studies/venice-private-inference/DEVPROOF-REPORT.md).
- **KMS opacity.** Most dstack-hosted services (including Phala KMS itself) are Stage 0: mutable image tags, no upgrade log, no third-party KMS review.
- **Tinfoil's external-config disk (router-only on this deployment).** Tinfoil closes the Phala/NEAR compose-hash backdoor (the attested `/config.yml` is hardware-bound via `tinfoil-config-hash=` in the SEV launch-measured cmdline). The container schema permits env vars and secrets sourced from a *separate, unmeasured* disk at boot, but auditing each enclave on `inference.tinfoil.sh` (2026-04-26) shows: the model-router has 2 such slots (`DOMAIN`, `USAGE_REPORTER_SECRET`) which a code trace establishes are off the prompt path; the per-model enclaves where prompts actually run (gpt-oss-120b, llama3-3-70b, gemma4-31b — `deepseek-v4-pro`, `kimi-k2-6` were unreachable for direct probe) have **zero** string-form env entries and **zero** `secrets:` — fully attested. Full critique: [tinfoil-confidential-inference case study](https://github.com/amiller/devproof-audits-guide/blob/main/case-studies/tinfoil-confidential-inference/DEVPROOF-REPORT.md).
- **Catalog ≠ served.** Some models advertised in a provider's `/models` list 404 on real calls — e.g. RedPill's Tinfoil-routed entries (`qwen3-coder-480b`, `deepseek-r1-0528`, `kimi-k2-thinking`) return 404 on `/v1/attestation/report` even though they appear in the catalog. Direct-Tinfoil (this registry's `tinfoil` provider) works end-to-end.

## Repo layout

```
awesome-private-inference/
  providers/*.md      one page per provider (claim / evidence / gaps / reproduce)
  verifiers/          attestation primitives — TDX, NRAS, per-provider shapes
  probes/             daily probe scripts + dashboard renderer
  data/snapshots/     JSON artifacts, one per CI run
  data/latest.json    symlink to most recent snapshot
  site/               (optional) extra static assets
  docs/               GitHub Pages output (generated)
  .github/workflows/  daily probe + page deploy + CI
```

## Run a probe locally

```bash
git clone https://github.com/amiller/awesome-private-inference
cd awesome-private-inference
uv venv && source .venv/bin/activate
uv pip install -e .

# Clone the NEAR AI verifier alongside (TDX primitives live there)
git clone https://github.com/nearai/nearai-cloud-verifier _nearai-verifier
export NEARAI_VERIFIER_PATH="$(pwd)/_nearai-verifier/py"

export NEAR_API_KEY=...        # optional
export REDPILL_API_KEY=...     # optional
export VENICE_API_KEY=...      # optional

python -m probes.collect
# writes data/snapshots/YYYY-MM-DD.json + docs/index.html
```

## Adding a provider

Copy `providers/_template.md`, add a shape dispatcher in `verifiers/`, register it in `probes/attestation.py`. See [CONTRIBUTING.md](./CONTRIBUTING.md).
