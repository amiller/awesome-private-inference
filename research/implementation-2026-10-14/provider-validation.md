# Candidate-provider validation and publication baseline

This is a read-only baseline for a route and reference observatory, observed 2026-10-14 UTC. It is **not** a successful private-inference audit. The route inventory in [`data/routes.json`](../../data/routes.json) identifies 19 client/path combinations and their potential plaintext holders. [`data/candidates.json`](../../data/candidates.json) keeps discovery and inclusion decisions separate from scored coverage. Public bytes are stored by SHA-256 under `data/references/observations/raw/`; each run has an immutable timestamped JSON file. [`data/references/latest.json`](../../data/references/latest.json) is a derived index and its `verification: not_performed` label is intentional.

The capture command was `python -m probes.references --catalogs`, using the repository's existing virtual environment, no install, inference request, message, purchase, or heavy build. Fetches require HTTPS, enforce a 2 MB body bound and 15-second timeout per source, and report per-source errors. Release metadata is GitHub API JSON, not a downloaded release asset. `write_index` keeps the last successful hash when a later fetch fails; source state transitions persist as immutable events with `event_id`, `kind/type`, route mapping and priority. The semantic catalog digest tracks model IDs and tier/provider routing so changing prices or opaque tariff IDs do not imply a new confidential route. Exact raw body hashes remain available for all captures.

## Maple blocked state and validation procedure

**Blocked at live client/session and upstream proof.** The public [proof page](https://www.trymaple.ai/proof) and pinned [source review](../review-2026-10-13/maple.md) support a source-level picture of Nitro PCR0 and two separate upstream routes. They do not establish the running EIF, chosen route or backend worker. Pin shipped web/native/proxy versions and source commit. With a harmless prompt, verify a fresh Nitro document's AWS chain, nonce, key, PCRs and same-session exchange; run EIF reproduction on a remote builder and compare PCR0/1/2 and artifact digest. Trace selected Tinfoil or Continuum forwarding and independently verify that backend. Test altered root, nonce, key, model and mirror disagreement before any prompt release. A passing row needs an authorized value covering every plaintext process and a request bound to it; no such row exists yet.

## Private Inference blocked state and validation procedure

**Blocked at credentialed quote and independent reference policy.** The [published explanation](https://privateinference.gg/how-it-works) distinguishes standard/ZDR from private beta and acknowledges the response-key issue. The preliminary [browser review](../review-2026-10-13/privateinference.md) found quote self-consistency checks but no approved compose/OS baseline in the inspected verifier; the captured verifier bytes still match that review. An unauthenticated `/v1/private/attestation` attempt returned 401. With an authorized test key, pin the served browser assets, capture a fresh model quote, verify TDX/GPU/key/compose evidence independently, and compare requested model and workload against a reviewed model-specific policy. Make a harmless encrypted request, mutate model, compose, OS, nonce and key, and confirm refusal before sending. Response confidentiality remains limited until the NEAR [response-key binding issue](https://github.com/nearai/cloud-api/issues/1061) is fixed and the fix is observed on this route. Standard and ZDR must never inherit the private-beta verdict.

## Privatemode blocked state and validation procedure

**Blocked at client-policy behavior and live worker chain.** The [proxy docs](https://docs.privatemode.ai/api/proxy-configuration/) specify auto-adoption of a latest manifest versus `--manifest-path` pinning; the [trust docs](https://docs.privatemode.ai/security/trust-and-compliance/) describe proxyless provider-side verification. Pin the exact captured manifest and proxy version, inspect Coordinator/secret-service/worker admission, reproduce manifest values on an appropriately sized remote builder, and test a pinned client's key exchange and harmless completion. Controlled manifest, CPU, GPU and mesh-certificate changes must reject before payload release. Test default refresh separately and record whether an update is merely logged or actually refused. Proxyless access needs its own plaintext and acceptance analysis.

## Confidential AI blocked state and validation procedure

**Blocked at signed release, quote, TLS and worker-route verification.** The [public source](https://github.com/confidential-dot-ai/confidential-inference) describes release assets and a verifier; [TEErminator](https://github.com/confidential-dot-ai/teerminator) specifies pinning against the same upstream TLS certificate. Match exact signed asset/commit/allowlist bytes to a fresh quote and workload receipts; independently validate TDX, nonce, TCB, Sigstore identity, TLS cert binding and raw GPU evidence using a compatible verifier. Run a harmless completion through the actual gateway/router/worker and inject wrong image, allowlist, nonce, cert and worker identity. The public [threat model](https://github.com/confidential-dot-ai/confidential-inference/blob/main/docs/threat-model.md) documents operator-key/cluster-admin and unencrypted control-plane-disk access paths. Resolve or explicitly exclude those paths with evidence before a confidentiality verdict. The prior nonce-echoing response was only a parser/reachability observation.

## Weekly discovery and review

Run `python -m probes.references --catalogs` weekly, archive the full run and model IDs, and compare route/tier assignments. Keep `probes/catalog.py` as a stable sentinel sample. Review new or retired catalog entries, source client policies, manifest/release changes and public SDK documentation against the owning route card. A provider publication change is an alert to inspect scope and authority; it is not automatic acceptance by a client. Do not promote candidate routes until the provider-specific blocked conditions above are closed with live request-bound evidence.
