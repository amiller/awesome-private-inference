## Tally

- 12 of 15 apps touch NEAR attestation; 9 verify the TDX quote signature. Seven do it locally with dcap-qvl: indaga, saferedline, triage, sealed-review, pixlz, promptbarrel, and Wrenai through the SDK. Symbolon uses NEAR One's on-chain verifier and NEXORA posts the quote to Phala's remote API. Attestra checks the quote only offline, and antrepreneur and TriagePay never check it.
- Six block the prompt before sending on a failed check: indaga, saferedline, triage, sealed-review, pixlz and Wrenai. NEXORA blocks too, but on weaker checks. The three contract apps (Symbolon, promptbarrel, Attestra) gate payment or verdict acceptance after the prompt has gone out. antrepreneur gates nothing.
- Five keep the prompt hidden from the app server: indaga (browser, E2EE v3), triage, sealed-review and pixlz (local), and promptbarrel in private mode. saferedline, NEXORA and Wrenai see plaintext on their own servers; Wrenai then encrypts to NEAR.
- Per-response signature (`/v1/signature`): every app that checks it does so after the reply arrives, so it never blocks the prompt. indaga shows the reply first and then a verdict badge. saferedline, triage, pixlz, NEXORA and Wrenai fold it into their verdict or discard the answer. Symbolon, promptbarrel and Attestra check it on-chain before paying or accepting a verdict, and antrepreneur's contract does the same. sealed-review and TriagePay don't check it.
- saferedline's server can return its own dstack quote (`src/server.mjs:194-198`), but only an offline script verifies that quote (`scripts/verify_server.mjs`). The browser doesn't check it before sending.
- E2EE: only indaga sends v3. Wrenai (SDK 0.2.0), sealed-review, promptbarrel and Attestra send v2, which doesn't bind the reply key. saferedline, triage and pixlz send no E2EE and pin TLS to the attested gateway, so NEAR's gateway reads the prompt.
- triage and saferedline require every model instance to verify. sealed-review reviews each machine, and its gate admits only reviewed keys. indaga and NEXORA check the first instance, pixlz accepts if any one passes, and Attestra uses the first key unverified.
- Only triage pins NEAR's OS and app identity. Symbolon and promptbarrel pin measurements on-chain, sealed-review relies on a person's signed review, and saferedline's pin is optional. Everyone else accepts any compose that MRCONFIGID binds.
- The deploy log (`compose_manager_attestation`) is checked by indaga, pixlz, sealed-review and the SDK. All four recompute `actions_hash`, so none repeats hermes's bug. Only sealed-review fails when the log is missing (`watcher/src/launcher.rs:290-297`); indaga, pixlz and SDK 0.2.0 (`dist/node.js:2540`) skip it.

## Shared code and recurring bugs

- **Stored event digests are trusted** (the known bug class): indaga (`event-log.mjs:15`) and promptbarrel (`attest-core/src/lib.rs:50-54`). In both, the only payload read is `compose-hash`, which is also checked against MRCONFIGID, so the exposure today is small. Any later read of `app-id` or `os-image-hash` would inherit the bug. saferedline, triage, pixlz, sealed-review and SDK 0.2.0 recompute every digest.
- **NRAS JWTs are decoded without a signature check** in NEXORA and antrepreneur. That is what NEAR's own near-examples/nearai-cloud-verification-example does (`utils/model-attestation.js:2,19`, `decodeJwt`), and that example doesn't verify the TDX quote at all. antrepreneur cites it. Both call NRAS over HTTPS directly, so the GPU verdict rests on that TLS connection alone, and the JWT can't be re-checked later from a stored proof.
- **`@phala/dcap-qvl` 0.7.0** is in indaga, triage, sealed-review, and Wrenai through inference-sdk 0.2.0. Version 0.7.1 (2026-11-03) requires the TCB Info and QE Identity signers to be issued directly by Intel's root. NEAR's SDK made 0.7.1 the minimum on 2026-11-11 (inference-sdk #179), and added a regression test in which collateral signed by an intermediate-issued PCK leaf must fail. That test fails against the previous build. saferedline, pixlz and promptbarrel already resolve 0.7.1.
- **OutOfDate accepted** by indaga (its comment says it copies NEAR's SDK), Wrenai (the SDK default), saferedline (its own set, citing the reference verifier) and pixlz (as WARN). triage, Symbolon and sealed-review fail it.
- **The gateway signer is trusted without its quote.** NEXORA accepts `signature_kind: gateway` against an address taken from the report. antrepreneur does the same, by the same pattern as the near-examples `extractSigningAddresses`.
- Prior work cited: NEAR's docs or reference verifier (saferedline, triage, indaga, Symbolon), near-examples (antrepreneur), and NEAR One's `tee-verifier` from near/mpc (Symbolon). No app cites teep, hermes, or the private-ai-gateway verifier. saferedline, sealed-review and Attestra ship AGENTS.md or CLAUDE.md files, so they were likely written with agents [i]. Nothing in the other repos says either way.
