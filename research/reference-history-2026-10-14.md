# Reference history graph

The new `docs/history.html` renders the stored history as a provider overview or separate reference surfaces. It is generated by `python -m probes.render` from historical snapshots, typed observations, retained reference publications and full-value review ledgers. No provider call or GitHub source fetch occurs during rendering.

The initial capture has 58 surfaces and 305 set transitions, plus 58 first-capture baselines. These counts include multiple descriptions of a workload and are **not** deployment counts. The four newly monitored providers mostly have only a baseline, making the historical coverage difference visible. Venice has no extracted reference value and appears as an explicit coverage gap, not a stable empty history.

Every point exposes full values, source evidence, previous observation time, evidence scope and exact-value ledger matches. Historical Tinfoil model enclaves remain separate from its router. Samples of a shared component within one run are combined into a set, avoiding an invented ordering of concurrent host observations. Revisiting an earlier set is distinct from first seeing a new set. Missing daily snapshot dates are shaded; empty tracks do not establish stability or retirement.

Magnitude has three inspectable dimensions:

- Added/removed entries in the observed set. Replacing one hash means two set edits, regardless of how much code changed.
- Added/removed lines between retained versions of the same text document. This is sensitive to formatting and minification and does not establish deployed source-code size.
- Related provider/model route cards. This is an inventory association, not a verified dependency graph or proven blast radius.

Deployed-code diff size is explicitly unknown. The current history generally lacks authenticated old/new source-to-artifact mappings. A useful next layer would attach pinned source commits and reproducible-build mappings to transitions, then separately count application, verifier, dependency, build, configuration and acceptance-policy changes. File/line counts would still describe review surface, not exploitability or audit effort.

Published JSON fields are shown as named digest-shaped leaves and policy keys. Chutes' retained golden-measurement rows and the NEAR anchor are included. Arbitrary permission/threshold edits are caught by document hashes but are not assigned a semantic security meaning. A provider's historical PCR list is observed as a set when fetched; its contents are not backdated as independently observed deployments. No inferred source mapping, cryptographic approval, or accepted-reference expansion is introduced.

Validation: 136 unit tests pass. `python3 tools/check_history_browser.py` uses the existing Playwright/Chromium installation to exercise provider/layer filters, component expansion, point selection, keyboard activation, search, JSON download, empty coverage and mobile overflow. It captures screenshots and exports a script-free preview with native links/disclosures for the artifact host. The repository page retains the full interactive controls. Preview and runtime state are kept under ignored `local-data/history-preview/`.
