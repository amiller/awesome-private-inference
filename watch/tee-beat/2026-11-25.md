## Code and releases

- **Dstack-TEE/dstack — [PR #1644](https://github.com/Dstack-TEE/dstack/pull/1644)
  "fix(kms/auth-eth): read app epoch at latest for env pubkeys" (merged
  2026-11-25T09:21:53Z)**: a newly registered app got no env pubkey for
  16–18 minutes because `getAppEpoch()` resolved the on-chain app epoch at
  `ETH_BLOCK_TAG` (default `finalized`) and `currentAppEpoch` reverts
  `AppNotRegistered` until registration reaches that block. The two env-pubkey
  RPCs (`GetAppEnvEncryptPubKey`, `GetSealedEnvPubKey`) now read at `latest` —
  they only need the root key, app id and epoch — while key release
  (`authorizeApp`, boot auth) still reads at the policy block, so a new app
  still boots only once registration reaches the policy block. After an
  `advanceAppEpoch` the pubkey switches to the new epoch immediately, so new
  secrets are never sealed to the retired key. Test asserts the `latest` read
  fails if reverted. No release carries it yet (latest remains
  sdk/go/ratls/v0.6.1 / v0.6.6 full stack).
