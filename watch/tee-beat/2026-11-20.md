## Code and releases

- **Dstack-TEE/dstack — `key-recovery-v0.6.5` released**
  ([release](https://github.com/Dstack-TEE/dstack/releases/tag/key-recovery-v0.6.5),
  2026-11-20T12:59:44Z): a new `dstack-key-recovery` tool
  ([PR #1632](https://github.com/Dstack-TEE/dstack/pull/1632), merged
  2026-11-20T12:53:50Z) that recovers an application key from an older KMS
  root epoch after rotation — the guest agent serves only its boot epoch. It
  reproduces both guest APIs (0.5.x v0 and 0.6.x v1), reads KMS URL, pinned
  CA, launch ticket and collateral from the CVM's config files, and can serve
  the recovered keys over a Unix socket/localhost HTTP. It must run inside the
  CVM (needs the platform quote; documented bind-mounts include
  `/dev/tdx_guest`, `/dev/vsock` and a CCEL outside `/sys`). Validated on a
  real 0.5.15 CVM against a live KMS preserving epoch 0: byte-identical to the
  agent's `getKey` at the current epoch and the epoch-0 root key with the
  epoch-0 KMS signature. Container
  `ghcr.io/dstack-tee/dstack-key-recovery:0.6.5`, digest
  `sha256:26803eb7eb34f69f367d7ebc0b4abc31f35caad5e58213de77a91dddcd2d0b6b`,
  built with provenance and SBOM; follow-up
  [PR #1633](https://github.com/Dstack-TEE/dstack/pull/1633) pins that digest
  in the docs with a Sigstore verification link. The disk key is
  instance-bound and is explicitly not recoverable with this tool.
- Dstack-TEE/dstack — [PR #1628](https://github.com/Dstack-TEE/dstack/pull/1628)
  (merged 2026-11-20T12:51:17Z) "load SEV-SNP TCB requirements from a JSON
  file in the verifier and the KMS": both now read the CPU governance's
  published minimum-TCB list (`sev_snp_tcb_requirements_file`) as the JSON
  governance publishes, instead of hand-rewritten TOML tables (which no
  release shipped). Precedence rules: in the KMS the published list decides
  and the file only fills gaps for CPUs governance does not list — a KMS
  carrying a file vouches by itself for those CPUs (refused on `next`); a
  malformed file stops the process at startup. Extends the
  [PR #1621](https://github.com/Dstack-TEE/dstack/pull/1621) TCB-status work
  reported 2026-11-19.
