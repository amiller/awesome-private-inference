## Code and releases

- **google/go-tdx-guest — [PR #125](https://github.com/google/go-tdx-guest/pull/125)
  "verify: reject quotes whose TDX Module TCB level is not UpToDate" (merged
  2026-11-26T17:00:17Z)**: verification behavior change. Since #89 the TDX
  Module Identity TCB level only decided whether a relaunch was advised; now
  `checkTcbInfoTcbStatus` also requires the matching TDX Module TCB level to
  be `UpToDate`, so when collateral is used and `DisableTcbStatusCheck` is
  not set, `TdxQuote` rejects quotes from TDs launched on a TDX module whose
  SVN the TCB info lists `OutOfDate` (returns `ErrTdxTcbStatus`) or
  `Revoked`. The PR matches Intel's QVL, where `convergeTcbStatuses` folds
  the TDX Module TCB status into the TDX TCB status. Anyone verifying quotes
  with this library should treat pre-#125 and post-#125 acceptance as
  different verifiers. Remains v0.3.1.
- **Dstack-TEE/dstack — [PR #1642](https://github.com/Dstack-TEE/dstack/pull/1642)
  "feat: Secure TSC for AMD SEV-SNP, and secure_time refuses a host-controlled
  clock" (merged 2026-11-27T06:58:26Z)**: without Secure TSC the SEV-SNP
  hypervisor can intercept RDTSC, so guest time was host-controlled between
  NTP syncs. Guests with `secure_time` on (the default when compose omits it)
  are now launched with `secure-tsc=on` and `SEV_FEATURES` bit 9 recorded in
  the measurement document; `dstack-mr` accepts `SNPActive | SecureTSC` in
  `guest_features`; `dstack-util` refuses to boot unless the clocksource is
  `tsc` and, on SNP, Secure TSC is active. Launching requires QEMU ≥ 11.2
  (only `v11.2.0-rc1` exists today) and host kernel ≥ 6.18; a mkosi kernel
  patch exposes the `sev_status` bit as
  `/sys/devices/system/cpu/sev/secure_tsc`. **Breaking**: apps with
  `secure_time` on no longer boot on AWS or on SNP hosts without Secure TSC;
  older verifiers/KMS reject such guests. Hardware-tested on EPYC 7763
  (Milan) with QEMU `v11.2.0-rc1`, kernel 6.18.59. No release carries it yet.
- Dstack-TEE/dstack — [PR #1655](https://github.com/Dstack-TEE/dstack/pull/1655)
  "feat(os/mkosi): ship the NVIDIA open modules' headers" (merged
  2026-11-27T00:38:07Z): the guest image installs the open-gpu-kernel-modules
  interface headers for driver 595.91.07 under `/usr/src/nvidia-595.91.07`

  are application/KMS-level, not OS-image or attestation changes — out of
  scope here. Remains sdk/go/ratls v0.6.1 as latest release.
- microsoft/openvmm — [PR #5292](https://github.com/microsoft/openvmm/pull/5292)
