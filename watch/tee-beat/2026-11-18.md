- **Dstack-TEE/dstack — large commit train 2026-11-18 morning (PRs
  #1603–#1619), headlined by formal verification and a gateway key-proof
  feature**; no release carries them yet (latest remains kms-v0.6.5-mrgk,
  v0.6.5).
  - [PR #1597](https://github.com/Dstack-TEE/dstack/pull/1597) "formal: add
    Lean proofs for KMS, gateway and guest OS logic" (merged
    2026-11-18T12:47Z): a Lean 4 project (`formal/`, no Mathlib) with
    hand-written models and machine-checked proofs of KMS root-epoch and
    handover invariants, KDF domain separation, RA-TLS encoding injectivity,
    gateway IP/port/cert logic, and guest event-log replay and boot
    measure-before-use; CI rejects `sorry`, `axiom` and `native_decide`. The
    proof work surfaced documented observations, several fixed in the same
    train: the dead exact-match cert branch and unchecked SNI label lengths
    fixed together (#1603), a gateway rejecting every node's wg key, not only
    its own (#1604), a shared IP kept allocated while another instance holds
    it (#1605), a warning when a peer gateway address sits in this node's
    pool (#1606), and a warning on a non-20-byte `instance_id_seed` (#1607).
  - [PR #1615](https://github.com/Dstack-TEE/dstack/pull/1615) "feat(gateway):
    let CVMs prove possession of their WireGuard key" (merged
    2026-11-18T11:43Z): closes a registration-squatting denial-of-service —
    a CVM that learned another CVM's public key could register under it and
    keep the victim out of rotation. Proof is HMAC-SHA256 keyed by
    HKDF(X25519(client_sk, gateway_pk)) over both keys, app id and instance
    id; cluster-wide policy switch, **off by default**; the attack is only
    closed once every node runs this and the policy requires proofs.
  - KMS refuses to serve from an empty keyring (#1618) with a formal model of
    the check (#1619, merged 2026-11-18T13:29Z).
  - VMM lifecycle fixes: keep running VMs that fail to load at startup
    (#1609), snapshot loaded VMs before directory scans on reload (#1610),
    serialize guest power-off records with launches (#1611), atomic VM
    manifest/state writes (#1612), recheck removal under the launch lock in
    stop_vm (#1613), keep the sealed env window when a start adopts a running
    VM (#1614), recheck started under the launch lock on auto-start (#1616),
    run each start to completion even if its request is dropped (#1617).
