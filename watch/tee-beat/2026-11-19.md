## Code and releases

- **Dstack-TEE/dstack — SEV-SNP attestation-verification hardening train,
  merged 2026-11-19T04:14–05:01Z**; no release carries it yet (latest remains
  kms-v0.6.5-mrgk / v0.6.5). Three verifier gaps fixed back-to-back, each
  disclosed in its PR body:
  - [PR #1620](https://github.com/Dstack-TEE/dstack/pull/1620) (merged
    2026-11-19T04:45Z): on the supplied-`cert_chain` path, `QuoteVerifier`
    checked the ARK→ASK→VCEK chain and the report signature but never that
    the VCEK belongs to the report's `chip_id` and `reported_tcb` (the KDS
    path was bound implicitly via URL construction). A VCEK from another
    chip, or one from an older TCB, could sign a report claiming any chip
    id and a newer TCB; since KMS derives `device_id` from
    `sha256(chip_id)`, this defeated the device allowlist. The existing mock
    test's VCEK carried no AMD extensions and still verified. Fix: after the
    report signature check, both paths now require the VCEK's AMD
    extensions to match the report's chip id and TCB; also accepts 64-byte
    Turin hwIDs.
  - [PR #1621](https://github.com/Dstack-TEE/dstack/pull/1621) (merged
    2026-11-19T04:54Z, stacked on #1620): SNP `tcb_status` previously meant
    only that reported/committed/launch TCBs are equal — a host on years-old
    vulnerable firmware still reported `UpToDate`, and
    `requireTcbUpToDate` gates on it, a false pass versus TDX semantics.
    AMD publishes no TCB status, so the verifier now judges reports against
    configured AMD bulletins (`[core.attestation]
    sev_snp_tcb_requirements`: product family, advisory ID, minimum fixing
    TCB); below-minimum TCBs surface in `advisory_ids`.
  - [PR #1622](https://github.com/Dstack-TEE/dstack/pull/1622) (merged
    2026-11-19T05:01Z): `sev-snp-qvl` never consulted AMD's CRL; a revoked
    ASK verified on both paths. Now checked on both paths against the
    product's CRL `<kds>/<product>/crl`, requiring the pinned ARK as issuer,
    a valid signature, currency (`thisUpdate <= now < nextUpdate`), and that
    the ASK serial is absent; CRLs cached one hour, a failed fetch surfaces
    as unavailable collateral.
  - Around them: [PR #1623](https://github.com/Dstack-TEE/dstack/pull/1623)
    (merged 2026-11-19T05:11Z) splits `DstackKms` against the 24 KiB
    EIP-170 limit by deploying app proxies through the `DstackApp`
    implementation (the motivation is that a per-platform TCB policy needs
    ~1.9 KB the contract no longer has); guest-agent watchdog keepalive fix
    ([PR #1625](https://github.com/Dstack-TEE/dstack/pull/1625), a Rocket
    15 s header-read timeout racing the heartbeat interval); and guest-agent
    access logging of every API and serial-console request with unix peer
    credentials ([PR #1626](https://github.com/Dstack-TEE/dstack/pull/1626)).
